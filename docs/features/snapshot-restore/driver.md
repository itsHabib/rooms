> Specs reflect design **v4** (`snapshot-fork-replay/spec.md`, third review pass — Fable): quiesce
> is verifiable via a vsock beacon before the `neutral` write; the base slot is transferred to a
> never-reclaim reservation token (not freed) to avoid a walk-allocator steal race; `snapshot.mem`
> is bind-mounted (not copied); witness/egress install before `Resumed`; the resume-apply agent is
> poll-retry (no held vsock across snapshot). See the spec §12 v4 changelog.

This phase is a **fully serial pipeline** — a security primitive, then the snapshot it gates,
then the restore that consumes the snapshot. No parallel batches; every pair conflicts on a
dependency edge (and shares `room.rs` + `main.rs` besides). All three are local-runtime,
opus/extra: new Firecracker API surface with correctness-critical ordering and a load-bearing
security invariant (neutrality-by-construction).
